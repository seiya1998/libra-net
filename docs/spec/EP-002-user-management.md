# EP-002: 利用者管理

由来: `requirements/EP-002-user-management.md`

> 利用者(Patron) / スタッフ(Staff) の2系統。利用者種別マスタ＋種別ごとの貸出ルール（値は EP-003）。認証は外部 IdP（ADR-007）。状態: `有効` / `停止` / `失効`。

## F-01: 利用者一覧・検索

### 概要

管理画面で利用者を検索・一覧し、詳細・編集への入口とする。

### 業務ルール

- テナントscope。一覧はカーソルページング（`performance.md`）。
- 既定では `失効` を除外（フィルタで含められる）。

### 画面 / インターフェース

- 検索フォーム: 氏名 / 識別子（学籍番号・従業員ID・図書カード番号）/ 利用者種別 / 所属 / 状態。
- 結果テーブル → 行から詳細(F-02) / 編集(F-04)。

### エラー条件

- なし（該当 0 件は空状態表示）。

### 由来 US

- US-004

## F-02: 利用者詳細

### 概要

利用者 1 人の情報・利用状況をまとめて表示する。

### 業務ルール

- 表示項目は requirements「利用者モデル」の共通＋種別固有。
- 個人情報の参照は監査記録（ADR-009）。お気に入り・履歴も個人情報として扱う。
- お気に入りの登録は利用者が OPAC で行う（EP-004）。ここでは閲覧のみ。

### 画面 / インターフェース

- プロフィール（共通＋種別固有）/ 状態・有効期限。
- 現在の貸出（返却期限含む）・貸出履歴・予約・延滞・お気に入り・図書カード。

### 由来 US

- US-004

## F-03: 利用者登録

### 概要

利用者を新規登録する。種別を選ぶと入力項目（共通＋種別固有）が切り替わる。学生・教職員は名簿（F-05）から、一般は来館本登録（F-06）から。

### 業務ルール

- 識別子（学籍番号 / 従業員ID / 図書カード番号）はテナント内一意。
- 認証情報は外部 IdP に作成（DB は IdP 参照のみ。ADR-007）。
- 種別は利用者種別マスタ（F-08）から選択。

### 画面 / インターフェース

- 種別選択 → 種別に応じた登録フォーム（共通＋種別固有）。

### エラー条件

- 識別子重複 / 必須項目欠落。

### 由来 US

- US-005, US-006

## F-04: 利用者編集・状態変更

### 概要

利用者情報の編集と、状態（`有効` / `停止` / `失効`）・有効期限の変更。

### 業務ルール

- **論理削除（物理削除しない）**。退会・卒業・退職・カード失効は状態・有効期限で表す（ADR-009）。完全削除要求時のみ PII マスキング（レコード・監査ログは保持。Q-022）。
- 利用停止は**区分**を選ぶ（一時停止＝期限内 Undo 可 / 永久停止＝管理者承認）。停止・解除は**操作確認（識別子入力）＋監査記録**（ADR-011）。
- 公開氏名（氏名 / 通称 / イニシャル）・督促時表示名・DV 配慮フラグを設定できる。
- 変更は監査記録（誰が・いつ）。

### 画面 / インターフェース

- 編集フォーム（公開氏名・通称・督促時表示名・DV 配慮含む）。状態・有効期限の変更操作（停止区分の選択・識別子で操作確認・理由記録）。

### エラー条件

- 不正な状態遷移。

### 由来 US

- US-004

## F-05: 名簿取込・ID 突合（学生・教職員）

### 概要

学籍番号 / 従業員ID で大学名簿と突合し、利用者を一括登録・更新する。

### 業務ルール

- CSV 一括取込＋手動（将来 大学認証基盤連携。Q-010）。
- 卒業・退職は名簿反映で `失効` にする。
- 取込はプレビュー → 検証（エラー行提示）→ 確定。実行者・結果を履歴に記録（ADR-009）。

### 画面 / インターフェース

- CSV アップロード → プレビュー → 検証結果 → 取込確定。テンプレート CSV ダウンロード。

### エラー条件

- 形式不正・必須列欠落・識別子重複 → 該当行をエラー提示（全体は止めない）。

### 由来 US

- US-005

## F-06: 電子図書カード発行（一般・来館本登録）

### 概要

OPAC の仮申込（→ EP-004）を受け、来館・本人確認のうえ本登録し、**電子図書カード（番号＋バーコード）を発行する**（印刷・物理カードは発行しない）。発行後、利用者は OPAC ログイン後にバーコードを表示してカウンターのスキャナにかざす（→ EP-004 / Figma O20 相当）。

### 業務ルール

- 本登録は**来館・本人確認必須**（免許証 / マイナンバーカード / 保険証 等。議事録）。
- 図書カード番号は一意・有効期限あり。提示した本人確認書類の種類を記録。
- カードは**電子**（OPAC でバーコード表示）。**印刷・物理カードは発行しない**。
- 番号の漏洩・無効化時は再発行（旧番号を失効し新番号を発行。履歴記録）。

### 画面 / インターフェース

- 仮申込一覧 → 本人確認入力 → 本登録 → **電子図書カード発行（番号採番・バーコード生成）**。発行後、利用者は OPAC でバーコードを表示。

### エラー条件

- 本人確認未完了での本登録不可 / カード番号重複。

### 由来 US

- US-006

## F-07: スタッフアカウント管理

### 概要

管理画面を運用する図書館スタッフ（司書等）のアカウントを管理する。一般の教員・事務員は対象外（彼らは利用者）。

### 業務ルール

- 所属キャンパス＋ロール（司書 / 館長 / システム管理者）を設定。状態（有効 / 無効）。
- 認証は外部 IdP（ADR-007）。ロールで操作範囲を制御（自館中心。EP-001 の権限・監査と整合）。
- 運営 / テナント横断の管理は EP-006 と関連。
- ログインは **MFA なし＋許可 IP 制御**（図書館ネットワーク等の固定 IP。テナントごとに許可 IP 設定。ADR-007 / Q-015）。
- スタッフの**追加・編集・無効化はシステム管理者ロール**が行う（司書・館長は不可）。**物理削除せず無効化**。初期管理者の発行はテナント開設時（EP-006）。ロール×操作の詳細権限は詳細設計（Q-017）。

### 画面 / インターフェース

- スタッフアカウント一覧 / 作成・編集（キャンパス・ロール・有効無効）。

### エラー条件

- ログインID 重複 / 権限不足。

### 由来 US

- （管理基盤。EP-001 の監査・権限 / EP-006 と関連）

## F-08: 利用者種別マスタ管理

### 概要

利用者種別（学生 / 教員 / 事務 / 一般 …）のマスタを管理し、種別ごとに貸出ルールを紐づける。

### 業務ルール

- 種別は追加可。種別ごとに識別子の種類（学籍番号 / 従業員ID / 図書カード番号）と貸出ルール（上限・期間 等。値は EP-003）を持つ。
- 既存利用者が紐づく種別の削除は不可（無効化で対応）。

### 画面 / インターフェース

- 種別一覧 / 作成・編集（名称・識別子種類・貸出ルール）。

### エラー条件

- 利用中の種別の削除 → 不可（警告）。

### 由来 US

- （管理基盤。EP-003 の貸出ルールと連携）

## F-09: 利用者代理モード

### 概要

司書が利用者本人として操作を代行する（高齢者・障害者支援。Figma A26 由来）。

### 業務ルール

- 代理操作中はその旨を明示。**全操作を監査ログに記録**し、本人のマイページにも履歴を開示（ADR-011）。
- 代理で行える範囲はロールで制御（パスワード変更等の機微操作は制限）。

### 画面 / インターフェース

- 対象利用者を選び代理モード開始 → OPAC 相当の画面で操作 → 代理操作履歴を表示。

### エラー条件

- 権限不足 / 機微操作の制限。

### 由来 US

- （支援機能。EP-004 OPAC と連携）
