# EP-002: 利用者管理

## 概要

司書（管理画面）が利用者を管理する。利用者は **学生 / 教職員 / 一般** を含む「利用者種別」で扱い、種別ごとに登録項目と貸出ルールが異なる。本を借りる **利用者（Patron）** と、管理画面を運用する **スタッフ（Staff）** を分ける。認証は外部 IdP に委譲する（ADR-007）。

## 利用者モデル（前提）

### アカウント体系（2系統）

- **利用者（Patron）**: OPAC を使い本を借りる人。大学（テナント）単位で共有し、**ホーム館**を持つ（どのキャンパスでも利用可＝相互利用）。
- **スタッフ（Staff）**: 管理画面を運用する図書館スタッフ（司書 / 館長 / システム管理者）。**所属キャンパス＋ロール**を持つ。**一般の教員・事務員は含まない（彼らは利用者）**。
- 司書は大学職員なので「教職員（利用者）」かつ「スタッフ」を併せ持つことがある。

### 利用者種別（マスタ・追加可）

種別を一覧（マスタ）で持ち、**種別ごとに貸出ルール（上限冊数・期間・予約上限・延長可否。値は EP-003）を紐づける**。

- 初期種別: **学生 / 教員 / 事務 / 一般**（将来 院生・研究員・非常勤 等を追加可）
- 識別子は種別で異なる: 学生=**学籍番号** / 教員・事務=**従業員ID** / 一般=**図書カード番号**

### 項目（共通＋種別固有）

- **共通**: 氏名 / 氏名カナ / **公開氏名（OPAC 表示。氏名 / 通称 / イニシャルから選択）** / 通称名 / **督促時表示名** / 連絡先（メール・電話・**保護者連絡先=任意**）/ **DV 配慮フラグ** / 利用者種別 / 状態（`有効` / `停止` / `失効`）/ 有効期限 / ホーム館 / 登録日
- **学生 固有**: 学籍番号 / 学部・学科 / 学年 / 入学年度 / 在籍期限（卒業予定）
- **教職員 固有**（教員・事務）: 従業員ID / 部署 / 職位
- **一般 固有**: 図書カード番号 / 住所 / 本人確認情報（提示書類の種類）
- 認証情報（パスワード等）は **DB に持たず外部 IdP**（ADR-007）。DB は IdP のユーザー参照のみ保持。
- 留年は項目に持たない（在籍状態と有効期限で表現）。

## ユーザーストーリー

### US-004: 利用者一覧・詳細の確認

- **As a** 司書
- **I want** 利用者一覧と各利用者の詳細（貸出状況など）を確認できる
- **So that** 利用者を管理できる

受け入れ条件:

- [ ] 種別 / 所属 / 状態 / 氏名・識別子 で絞り込み一覧できる
- [ ] 利用者詳細で、現在の貸出状況（返却期限含む）・貸出履歴・予約・延滞・お気に入り・図書カードを確認できる（お気に入り登録は EP-004）
- [ ] 状態（`有効` / `停止` / `失効`）と有効期限を確認・変更できる
- [ ] 利用停止は**区分（一時停止＝期限内 Undo 可 / 永久停止＝管理者承認）**を選べ、操作確認（識別子入力）と監査記録を伴う。停止解除も可能

### US-005: 学生・教職員の ID 突合

- **As a** 司書
- **I want** 学籍番号 / 従業員ID で大学名簿と突合して登録・更新できる
- **So that** 大学の構成員を正しく識別できる

受け入れ条件:

- [ ] 学籍番号 / 従業員ID で名簿と突合して登録・更新できる
- [ ] 名簿は CSV 一括取込＋手動で取り込める（将来 大学認証基盤連携。Q-010）
- [ ] 卒業・退職を名簿反映で `失効` にできる

### US-006: 一般利用者の登録（仮申込 → 来館本登録）

- **As a** 一般利用者 / 司書
- **I want** 一般利用者が OPAC で仮申込し、来館・本人確認のうえ本登録して図書カードを受け取れる
- **So that** 利便性を上げつつ不正登録を防げる

受け入れ条件:

- [ ] 一般利用者は OPAC で仮申込できる（→ EP-004）
- [ ] 来館して本人確認（**免許証 / マイナンバーカード / 保険証** 等）を経て本登録する
- [ ] 本登録で**電子図書カード**（番号は一意・有効期限あり、**印刷/物理カードなし**）を発行する
- [ ] 利用者は **OPAC ログイン後にバーコードを表示**できる（カウンターのスキャナにかざす。→ EP-004）
- [ ] 番号の漏洩・無効化時は再発行できる（旧番号を失効。履歴記録）

## 業務ルール

- 利用者は大学（テナント）単位で共有。ホーム館を持つが全館で利用可（相互利用）。
- 識別子（学籍番号 / 従業員ID / 図書カード番号）はテナント内一意。
- **論理削除（物理削除しない）**。退会・卒業・退職・カード失効は **状態（`停止` / `失効`）と有効期限**で表す（ADR-009）。個人情報の完全削除要求時のみ該当 PII をマスキング（レコード・参照整合・監査ログは保持。Q-022）。
- 一般の本登録は **来館・本人確認必須**（不正登録防止。議事録）。OPAC からは**仮申込のみ**。
- 認証は外部 IdP に委譲し、**パスワードを DB に保存しない**（ADR-007）。
- 個人情報（連絡先・住所・本人確認情報）の参照・変更は **監査記録**（誰が・いつ。ADR-009）。
- 利用者は共通の **利用者ID（PK）** で一意に識別し、貸出・予約はそれを参照（物理構造は schema で確定。Q-012）。
- **種別変更・名寄せ**: 1人=1利用者レコード。種別は変更可能（変更履歴を残す。例 一般→学生、卒業→一般）。重複登録は識別子一意＋本人確認で防ぐ。
- **自己情報変更**: 利用者は OPAC で連絡先・パスワードを変更できる（詳細は EP-004）。
- **図書カード再発行**: 紛失時は旧カードを失効し新カードを発行（履歴記録）。
- **スタッフ管理**: スタッフアカウントの追加・編集・無効化は**システム管理者ロール**が行う（物理削除せず無効化）。テナント開設時の初期管理者発行は EP-006（運営）。
- **利用停止の区分**: 一時停止（期限内は Undo 可）/ 永久停止（管理者承認）。停止・解除は操作確認（識別子入力）と監査記録（ADR-011）。延滞による自動停止は EP-003。
- **DV 配慮・公開氏名**: DV 等の配慮対象は連絡先・氏名の取扱いに制限。OPAC マイページや督促での表示名（公開氏名: 氏名 / 通称 / イニシャル）を選べる。
- **代理モード**: 司書が利用者本人として操作を代行できる（高齢者・障害者支援）。全操作を監査ログに記録し、本人のマイページにも履歴を開示（ADR-011）。

## 制約 / 非機能要件

- 認証は外部マネージド IdP（ADR-007）。当面 **番号（学籍番号 / 従業員ID / 図書カード番号）＋ パスワード**（メールはログインに使わない）、SNS なし、将来テナント別 SSO 余地。
- **OPAC（利用者）ログインは MFA 必須**（方式はメール OTP 推奨 / SMS / TOTP。Q-014）。**管理画面（スタッフ）は MFA なし＋許可 IP 制御**（テナントごとに許可 IP。Q-015）（ADR-007）。
- 個人情報保護（最小権限・アクセス制御・監査）。
- 全データはテナントscope（`tenant_id`。ADR-002）。
