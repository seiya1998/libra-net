# EP-006: マルチテナント SaaS

## 概要

契約大学ごとに同一システム/OPAC を展開する SaaS。契約完了でドメインを自動発行し、大学ごとにサイトのカラーテーマをカスタマイズできる。複数大学のデータを一元的に蓄積し横断活用する。

## ユーザーストーリー

### US-017: サブドメイン自動発行

- **As a** 運営者
- **I want** 契約完了時に大学ごとのサブドメイン（例 `{univ}.libriori.com`）を自動発行する
- **So that** 複数大学が同じシステムを展開できる

### US-018: 大学ごとのカラーテーマ設定

- **As a** 大学管理者
- **I want** プライマリカラー等を UI（カラーコード/ピッカー）で設定できる
- **So that** 大学ごとにサイトデザインを差別化できる

### US-019: 複数大学データの横断活用

- **As a** 運営者
- **I want** 複数大学のデータを集計し活用できる（蔵書導入計画の参考、著名人/教授のおすすめリスト等）
- **So that** SaaS としての独自価値を出せる

## 制約 / 非機能要件

- テナント分離 = PostgreSQL の **Pool（共有スキーマ＋行レベル `tenant_id`）＋ RLS**（リポジトリ＋型＋RLS＋テストの多層防御。→ ADR-002）。強セキュリティ大学は Hybrid で Silo に切り出し。
- 横断活用は**明示的な専用 read-only パス**で行う（**匿名・集計値・大学ごとオプトイン**。通常のテナントscope 越境はしない。Silo 大学は対象外。Q-021）。
