# 要件定義

エピック単位で `EP-NNN-{domain}.md` に分割する。新規エピックは `_template.md` を複製して作成。

- ストーリー（`US-NNN`）は**全体通し連番**。エピック内でリセットしない。
- 非機能要件・スコープ外・横断事項は本 README に記載する。
- spec/ と 1:1 でミラーする（同名ファイル）。

## 非機能要件 / 横断事項

- **組織モデル**: テナント = 大学（OPAC・サブドメインは大学に1つ）。1大学に **1〜複数キャンパス（1キャンパスも可）**、各キャンパスに図書館と司書（管理画面ユーザー）。**書誌は大学で共有・所蔵はキャンパス単位**。司書は自館の所蔵を管理し、書誌は全館で共有・編集可。**配送・返送・相互利用は複数キャンパス時のみ機能**（1キャンパスでは館選択を省略）（ADR-010。詳細は EP-002 / EP-005 / EP-006）。
- **マルチテナント**: PostgreSQL の **Pool（共有スキーマ＋行レベル `tenant_id`）＋ RLS**。分離はリポジトリ＋型＋RLS＋テストの多層防御。強セキュリティ大学は Hybrid で Silo に切り出し（ADR-002）。
- **OPAC**: モバイル前提・公開ページゆえ SEO/初期表示速度を重視。
- **外部連携**: 腐敗防止層で隔離、不通時もコア処理を止めない（ADR-003）。
- **認証**: 外部マネージド IdP に委譲（DB にパスワード非保存）。**番号（学籍番号 / 従業員ID / 図書カード番号）＋ パスワード**でログイン（メールはログインに使わない）、SNS なし、将来テナント別 SSO 余地（ADR-007）。SaaS 管理者は**二段階認証（TOTP）＋ IP ホワイトリスト**。パスワード再発行は OPAC/管理画面共通のメールで。
- **アクセシビリティ**: OPAC は **WCAG AA 以上**を目標。フォントサイズ（標準/大/特大）・ふりがな（読解レベル調整）・**代替テキスト必須**・スクリーンリーダー対応・言語切替・ダークモードを備える（公共性が高いため）。お知らせ等の文面も読解レベルに配慮。
- **監査ログ**: 管理操作（停止・督促一括・代理モード・テナント設定変更・蔵書/貸出操作・認証等）は **改竄不可・追記型の監査ログ**に記録し、ビューアで参照（操作者・ロール・対象・日時・IP・重要度。ADR-011）。
