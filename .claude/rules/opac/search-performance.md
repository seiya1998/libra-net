# 検索パフォーマンスルール（OPAC 蔵書検索）

OPAC の中核は蔵書検索。検索の体感速度・効率・SEO を最優先する。

## 検索状態は URL（searchParams）が source of truth

- **YOU MUST**: 検索条件（キーワード・フィルタ・ページ・ソート）は **URL の `searchParams`** に持つ。
  - サーバーでレンダリング・キャッシュでき、共有 / ブックマーク / 戻る・進むが効き、初期結果を SSR できる（SEO 両取り）。
- **NEVER**: 検索状態をクライアント state だけに持ち、URL へ反映しない。

## 入力と応答性

- **YOU MUST**: 検索入力はデバウンスする（過剰リクエスト抑制）。
- クライアント側の絞り込み・並べ替えは `useTransition` / `useDeferredValue` で非ブロッキングにする。
- **YOU MUST**: 結果はサーバー取得（RSC）＋ Suspense streaming で、スケルトンを先に表示する。

## 取得とページング

- **YOU MUST**: ページネーション（カーソル推奨）。既定件数・最大件数を決め、全件取得しない。
- **NEVER**: 全蔵書を取得してクライアントで絞り込む。
- ウォーターフォール回避: 独立した取得は並列化する。

## キャッシュと重複排除

- **YOU MUST**: 同一リクエストは React `cache()` で重複排除する。
- 検索結果は鮮度要件に応じて `revalidate` / キャッシュタグでキャッシュする。

## 体感速度

- `next/link` の prefetch、結果カードのホバー prefetch を活用。
- 書影は `next/image`（サイズ指定・遅延読み込み）で最適化。

## バックエンド連携

- 全文検索インデックス・クエリ最適化は **server（infrastructure / リポジトリ）側**の責務。opac は「必要な分だけ・並列で・キャッシュして取得する」ことに責任を持つ。
