# ロギング / 可観測性規約

マルチテナント SaaS では「**どのテナントの・どのリクエストの**ログか」を追えることが必須。

## 構造化ログ

- **YOU MUST**: **構造化ログ**（Fastify 標準の **pino**）を使い、JSON で出力する。
- **YOU MUST**: **全ログに `tenant_id` と `request-id`（相関ID）を付与**する。リクエストごとに request-id を発行し、ログコンテキストに乗せる。
- ログレベルを適切に使い分ける（`debug` / `info` / `warn` / `error`）。リクエスト/レスポンスは Fastify 標準ログを基本に。

## 秘密情報

- **NEVER**: 秘密情報・個人情報・トークン・パスワードをログに出さない（`security.md`）。必要なら redact する。

## エラー監視

- `Result` の失敗（特に 5xx）はログに記録し、**監視基盤（Sentry / Datadog 等）**へ送る（ベンダーは別途選定）。
- 監視に十分な文脈（`tenant_id`・`request-id`・操作名）を含める。

## 非同期ジョブ

- **YOU MUST**: 非同期処理（`async-jobs.md`）も**同じ `tenant_id` / 相関ID を引き継ぐ**（リクエスト経路外でも追跡可能に）。

## 原則

- ログは観測の手段。過剰ログを避け、**境界（入出力）・エラー・重要イベント**に絞る。
