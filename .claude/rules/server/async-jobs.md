# 非同期処理規約

返却日通知・予約順番通知・延滞検出・NDL 同期・カレンダー連携などの非同期処理は、**HTTP と並ぶ別の入口**から同じ application ユースケースを実行する。

## 原則（ランタイム非依存）

- **YOU MUST**: 非同期処理は application の**ユースケースを呼ぶ**だけにする（domain 不変）。
- **YOU MUST**: ジョブは**冪等**（同一ジョブが複数回実行されても安全）・**リトライ前提**で設計する。
- **NEVER**: 非同期の**具体ランタイム（ワーカー＋キュー / Lambda・バッチ）に application/domain を依存させない**（トリガ・SDK を内側に持ち込まない）。※ランタイム選定は未決（ADR-006）。
- **NEVER**: リクエスト経路（HTTP ハンドラ）で重い処理を同期実行しない（非同期に逃がす）。

## トリガの種類

- **スケジュール**（延滞検出・NDL 定期同期 など）と**イベント駆動**（貸出時に返却日通知を予約 など）の両方を想定。
- 起動は infrastructure / presentation 側のアダプタが担い、application ユースケースに渡す。
