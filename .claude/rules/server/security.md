# サーバーセキュリティルール

API は実データと認証情報を扱う。外部入力は信用しない。

## 認証・認可

- **YOU MUST**: 認可はリクエストごとに検証する。**multi-layer**（middleware だけに依存しない）。
- **YOU MUST**: リソース所有者 / ロールのチェックをユースケース（application）または handler で行う。
- **認証は独自認証**（学籍番号 / 従業員ID / 図書カード番号で突合。SSO なし）。パスワードは **argon2 / bcrypt 等でハッシュ化**し平文保存しない。セッション/トークンを安全に管理。番号（学籍/図書カード）は一意制約で重複登録を防ぐ。

## テナント分離（重要）

- **YOU MUST**: テナント分離は **MySQL に RLS が無い**前提で、**リポジトリ層の `tenant_id` 強制 ＋ 型での必須化 ＋ 分離テスト**で担保する（`multi-tenancy.md`）。
- **NEVER**: クライアント提供の `tenant_id` を信用しない。テナント越境アクセス（他大学の蔵書/利用者/貸出）を許さない。

## 入力検証

- **YOU MUST**: リクエストは JSON Schema で検証（`schema.md`）し、さらにドメインの不変条件で再検証する。
- **NEVER**: 検証していない外部入力をそのまま信用・実行しない。

## インジェクション対策

- **YOU MUST**: Drizzle のクエリビルダ／プレースホルダを使う。**NEVER** 生 SQL の文字列結合（SQL インジェクション防止）。

## 秘密情報

- **YOU MUST**: 認証情報・API キー・接続文字列は環境変数等で管理する。
- **NEVER**: 秘密情報・個人情報・トークン・パスワードをレスポンスやログに出力しない。

## 公開面の保護

- 公開エンドポイントにはレート制限を入れる。
- CORS は許可オリジンを明示する（ワイルドカード濫用禁止）。
